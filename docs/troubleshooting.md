# 故障排查

## 先确认本地状态

```sh
codex-switch version
codex-switch list
codex-switch doctor
codex-switch logs
```

`doctor` 检查本地认证、配置、账户库及原生 CLI，不查询额度、不刷新凭据。`status` 用于查看账户及额度，`status <ID> --refresh` 主动重新查询。

日志记录操作 ID、目标账户 ID、阶段和结果，不保存密钥或原始错误正文。日志仍包含账户及会话标识，反馈问题前请脱敏。不要上传 `auth.json`、账户库、备份或含密钥的 TOML。

## 无法切换或配置被外部修改

| 提示或现象 | 处理方式 |
| --- | --- |
| 存在 CLI、IDE 集成或 daemon | 按提示退出对应 PID 的任务，或明确选择强制切换 |
| 进程归属无法确认 | 检查提示的 Codex 目录和进程来源；工具不会扩大范围终止无关应用 |
| 当前认证不属于已管理账户 | 先用 `add chatgpt <备注> --current` 保存有效的官方登录，或还原外部修改 |
| 账户库绑定另一 Codex 目录 | 使用原目录，或为新目录指定独立 `--store` |
| 另一个账户管理操作正在运行 | 等待另一个操作结束，不删除锁文件绕过锁 |
| 切换完成但 APP 没打开 | 正常行为；切换后手动打开 APP 或 CLI |

```sh
codex-switch use <ID> --force
```

强制切换会中断关联任务，不结束无关 IDE 或其他 Codex 目录的进程。无法安全停止的进程仍会阻止切换。切换失败页面提供重试和返回，不应把失败当成成功。

其他配置工具持续写入同一 `CODEX_HOME` 会造成冲突。保留它们对其他客户端的管理，但关闭其针对 Codex 的接管、自动同步或配置写入。

## 官方凭据失效

官方凭据不是永久有效。切换时工具先检查有效期，使用官方 CLI 刷新；需要重新登录时显示认证流程。主动重新认证可运行：

```sh
codex-switch login <ID>
```

请登录原身份和原工作空间。网络异常、登录被撤销或工作空间不匹配会阻止切换；不要自行编辑 token。已保存的新凭据不会因后续取消而被旧认证覆盖。

官方认证和额度查询依赖原生 Codex 协议；升级客户端后出现协议错误，先记录 Codex 与 codex-switch 版本，再按项目兼容性测试结果处理。查询失败不能据此判断订阅已经失效。

## 中断恢复与提交后警告

发现 `pending.enc` 时先运行：

```sh
codex-switch recover
codex-switch doctor
```

恢复会根据事务记录处理配置与账户状态，不自动打开客户端。不要直接删除 `pending.enc`。目录不匹配、凭据或配置被再次修改时，恢复可能拒绝覆盖；保留现场并反馈脱敏后的提示。

「已切换，日志保存失败」等提交后警告表示账户可能已经生效。先查看 `doctor` 和当前状态，不反复切换或手动覆盖配置。会话副本结果未确认时也先检查客户端会话列表，避免重复创建。

## 第三方模型、额度和图片

先查看账户详情中的接口、默认模型、目录模式及额度配置。模型列表是本地配置，不能证明上游可用；额度接口也可能与模型接口采用不同的授权方式。

图片失败需要查看客户端的实际请求及上游返回：`model_not_found` 通常表示当前 Key 所属分组不能路由请求的图片模型。请服务商检查模型映射与权限。配置中的图片授权 Header 和功能开关只能表达客户端设置，不能授予上游未开放的能力。

导入样例中的 `model_provider = "OpenAI"` 可以被解析，但工具启用第三方账户时使用内部标识 `codex_switch`，官方账户使用 `openai`。名称大小写或伪装成官方名称不能解决图片路由问题。详见[服务商配置](providers.md)。

## 旧会话打开后无法发送

旧会话可能记住创建时的 provider。切换后若提示 provider 不存在，先确认当前配置正确，再用「会话接续」或以下命令创建副本：

```sh
codex-switch sessions
codex-switch sessions <旧会话ID>
codex resume <新会话ID>
```

同一 provider 的会话不出现在候选列表，直接打开原会话即可。第三方账户共用内部 provider 标识，因此两个第三方账户之间通常无需接续，但模型与历史工具仍需上游兼容。

接续保留原会话，不改写历史文件、不迁移远端响应状态，也不发送模型请求。目标上游不接受历史图片、工具或推理记录时，副本仍可能无法发送；此时新建会话并提供必要上下文。

## Keychain 与备份

无法访问 Keychain 时先解锁系统钥匙串。账户库与其 Keychain 密钥必须配套；已有库的密钥丢失时工具拒绝创建替代密钥，以免覆盖数据。跨机器迁移使用密码备份，详见[使用指南](usage.md)。

备份密码丢失无法恢复。恢复只接受空账户库；不要为导入而删除现有库。可指定新的 `--store` 进行恢复，再核对内容。
